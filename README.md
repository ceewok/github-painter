# GitHub Painter

A buildless, browser-local contribution graph editor. Open `index.html` in a browser, or serve this folder with any static web server. No packages or account tokens are required by the website.

Choose a year and paint or erase dates. Drag across cells, right-click to erase, or use arrow keys and Space. Four shades generate 1, 5, 10, or 20 commits per date. Undo restores a stroke; drawings are saved locally per year. Future UTC dates are disabled.

Enter a repository name and a commit email associated with your GitHub account, then download the Python script. With Python 3 and Git installed:

```sh
python contribution-art.py
# Or create the repository AND publish with an authenticated GitHub CLI:
gh auth login
python contribution-art.py --publish
# Optional private repository:
python contribution-art.py --publish --private
```

Set your Git `user.name` first, or supply `--name "Your Name"`. Run the downloaded script in the parent folder where you want the new repository. It refuses to overwrite existing folders unless you explicitly request `--resume`. Publication errors preserve the local repository for inspection and retry.

### Recovering an interrupted run

Refresh the website and download an updated script with the **same painting, repository name, and email**. Replace the old script in the parent folder, then run:

```sh
python contribution-art.py --resume
```

This works with repositories generated by the original script too. It checks the saved artwork and existing commit messages, dates, and author email, preserves completed commits, and adds only missing commits. It also handles the original script stopping after staging an unfinished mark. Edited artwork, unrelated changes, and unexpected history are rejected. Don't delete the partially created folder.

The updated generator batches commits with `git fast-import`, prints progress every 100 commits, verifies the final count, and gives a clean recovery message on Ctrl+C. A 5-minute import timeout prevents an indefinite wait. If Git remains slow in a OneDrive-synced folder, copy the script and generated repository together to a non-synced parent folder and resume there.

To publish a completed local repository, run the printed `gh repo create ...` command from inside it. If the remote repository was already created, use `git push origin main` instead.

The script makes real file-changing commits on `main`, setting both author and committer dates to noon UTC on painted dates. Repository creation itself happens now; only commit history is backdated. The repository explicitly identifies itself as generated artwork.

GitHub requires the commit email to belong to your account and commits to be on the repository's default branch. A newly created standalone repository is used, rather than a fork. Contributions may take up to 24 hours to appear. Enable private contribution visibility if using a private repository. Existing activity adds to the result, and GitHub's color scaling means the preview shades cannot be guaranteed.

See [GitHub's contribution reference](https://docs.github.com/en/account-and-profile/reference/profile-contributions-reference) and [troubleshooting missing contributions](https://docs.github.com/en/account-and-profile/how-tos/contribution-settings/troubleshooting-missing-contributions).

## Verification

Run `node --check main.js`, `node test.js`, then `python test-script.py`. Tests validate calendar interactions and execute the actual generated Python script against temporary Git repositories: fresh generation, repeat resume, recovery from an older partial run, preservation of existing commits, rejection of edits, exact dates and counts, and a full 7,320-commit year. Tests never publish or contact GitHub.
